# F11 Validation Guide

Use the pinned .NET SDK and a normal Windows 11 x64 session. Use the isolated state, catalog and desktop arguments documented in F10. Keep the diagnostic directory beside the isolated profile. Run Core preference and diagnostic checks before Windows acceptance.

1. Open Settings by keyboard. Save dark, light and system modes, cancel a change, set mute and relaunch Studio. Compare unrelated profile fields and verify high contrast/system preference through actual Windows tests.
2. In the F10 published fixture flow, launch a valid target, a disabled animation and a missing host. Check exact typed stage, result and fallback in the diagnostic view. Exercise inaccessible, malformed and unknown log data and confirm the same launch outcomes.
3. Fill the store through the count and byte limits and compare both generations. Inject identifying strings through target paths and command lines, and verify zero matching text in storage and the copied summary.
4. Verify the selected entry's health and explicit repair from diagnostics, including conflict, missing selection and preserved third-party files.
5. Record real process/UI evidence, regressions and limitations in evidence.md. Restore any changed Windows settings.
