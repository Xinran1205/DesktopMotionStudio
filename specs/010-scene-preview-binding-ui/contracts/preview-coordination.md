# Preview coordination contract

- PreviewRequest contains only generated requestId, validated immutable playback and display mode. The session boundary exposes Started/Completion/error and owned disposal, with no target/handoff/dispatch API. The MotionHost adapter always constructs Mode=Preview and reserves duration+500ms within10s.
- A single asynchronous command loop owns the active session. Play/Stop/owner-close use monotonically increasing tickets; a superseded queued request never creates a host. Before another Start, the previous session's disposal must finish. Obsolete cancel/completion cannot affect a newer session.
- Play returns a request-bound structured Completed/Skipped/Stopped/Superseded/Unavailable/Failed/OwnerClosed result. Invalid or pre-cancelled input creates no host and leaves an existing preview unchanged. Started is bounded3s (connect1s+Ready1s+Started750ms plus scheduling); playback10s; owned cleanup2s. Cleanup failure is visible and blocks further starts, preventing overlap with uncertain ownership.
- Stop has no target authority and awaits owned cleanup; owner-close is idempotent, closes pending/active preview, rejects future Play and awaits the command worker. External cancellation is request-ticket-bound. No profile/catalog writes or UI dispatcher occur in Core.
- Current is an immutable snapshot with generation/request/scene/phase/error. StateChanged is an invalidation signal: UI dispatches and reads Current at application time, avoiding queued stale state payloads. Observer failure must not interrupt resource cleanup. Actual UI wiring/recovery are T017/T018.
