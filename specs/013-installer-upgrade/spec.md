# Feature Specification — F12 安装、升级与卸载

**Feature Branch** `codex/f12-installer-upgrade`

**Created** 2026-11-03 · **Updated** 2026-11-07 · **Status** Accepted on Windows workstation

**Input** PRD V1.0 发行与恢复，TDD V1.0 §9，F02 配置、F10 入口所有权和 F11 诊断合同。

## User Scenarios & Testing

### User Story 1 — 离线按用户安装并启动 (P1)

普通用户从本地安装包安装 Studio，在 Windows 已安装应用中找到它，并打开 Studio。用户创建受管桌面入口后，即使 Studio 已关闭也能使用。

**Independent Test** 在 Windows 11 x64 普通交互会话中，以非提升权限从本地候选包安装。验证开始菜单和已安装 Launcher 的 Shell 启动，使用独立目标和本地测试快捷方式，记录随包运行时与原生降级结果。

1. **AC-01** 安装无需管理员权限、网络或预装项目运行时。安装成功后有当前用户范围内的 Windows 卸载入口和可打开的 Studio 入口。
2. **AC-02** 实际安装包含 Studio、Launcher、MotionHost 和兼容的内置作品。关闭 Studio 后，安装版 Launcher 通过受管入口调度一个目标，正常播放，或在渲染不可用时走原生降级。
3. **AC-03** 不兼容平台、占用或不可用的安装位置、无效或不完整的包必须明确失败。未确认归属的安装目标或快捷方式不得被覆盖。取消安装后无可见的成功注册或半套可启动程序。

### User Story 2 — 保持路径和数据的升级 (P1)

用户从已有版本升级。原受管入口、配置和偏好继续使用。升级失败后能重新使用升级前版本。

**Independent Test** 安装版本 A，建立绑定和受管入口并记录字节。安装版本 B，先在文件切换边界模拟可控失败再成功完成。

1. **AC-04** 支持同一产品标识的已验证相邻版本升级。成功后 Launcher 的可执行路径和受管入口字节保持一致，配置、备份、绑定、偏好和非程序用户文件保持完整。
2. **AC-05** 在提交前故意失败或取消，安装注册和可运行程序恢复到旧版本。重试可成功。异常终止若需恢复，在下一次安装操作中得到明确状态与可执行恢复路径。
3. **AC-06** 旧包不能覆盖新版本。重复操作不能产生第二套注册或入口。正在运行的 Studio/Launcher/MotionHost 应得到可执行的关闭或重试提示，不终止目标应用，也不要求重启才能正常完成标准路径。

### User Story 3 — 安全卸载并可重新安装 (P1)

用户在 Windows 已安装应用中卸载。明确获知哪些数据保留，以及有哪些快捷方式需手工处理。

**Independent Test** 执行当前用户注册的卸载命令，验证程序、开始菜单和卸载注册移除。通过隔离目录模拟完好、修改、替换、移动和缺失的受管入口，逐一核对身份和字节。重装验证保留的配置。

1. **AC-07** 卸载移除当前用户的程序注册和安装包拥有的程序文件。通过 F10 所有权验证删除当前 Desktop 中仍属于 Studio 的入口，且只清理可证明属于本产品的临时文件。
2. **AC-08** 修改、替换、移走、重定向或无法验证的入口一律保留。部分清理、占用或不支持的目录必须可识别，并告知用户剩余入口可能需要手工处理。第三方文件和注册保持完整。
3. **AC-09** 默认保留配置、备份和本地诊断。卸载入口或安装使用说明明确说明保留位置和重装行为。重装能读取原配置。无法确认的清理记录应保留，便于后续人工处理或重试。

## Functional Requirements

- **FR-001** 提供可复现的 Windows 11 x64 当前用户安装包。包包含普通用户离线启动所需程序和运行时，并注册当前用户的启动及卸载入口。
- **FR-002** 稳定产品标识及 Launcher 路径跨同一产品升级保持一致。发布版本必须可排序并独立于配置、诊断和 IPC 格式版本。
- **FR-003** 安装和升级在成功前验证平台、当前版本、包及目标可用性，提供可识别的取消、失败、占用和回退结果。升级失败保留或恢复完整旧版，并支持重试。
- **FR-004** 在普通卸载时仅处理有可验证所有权的安装文件和入口。升级中移除旧程序的内部操作不触发用户入口或数据清理。
- **FR-005** 卸载保留配置、备份、诊断及未解决的所有权证据。不得遍历并删除整个 Desktop 或数据根目录，不得写入第三方目录、机器级设置或默认协议关联。
- **FR-006** 发布构建输出版本、包 SHA256、依赖及分发来源说明。开发验证包的签名状态明确，公开发行的签名策略另行通过发布门禁。
- **FR-007** 安装、升级、回滚、卸载及部分清理以本机结果或有限诊断说明。帮助信息应能区分程序已移除、配置保留和部分入口保留。
- **FR-008** 正常安装版入口在升级准备期间仍能启动已提交版本。程序切换和卸载仍须保护启动中的程序。卸载意图已提交时拒绝新启动。
- **FR-009** 升级成功后保留当前程序版本和直接上一版用于恢复。更旧代只有在目录身份、清单和文件内容可验证时才回收。占用或无法验证的条目保留，后续同版本修复或升级可重新尝试回收。
- **FR-010** 暂存准备失败或发布遇到冲突时，移除本次操作已记录身份的暂存文件与空目录。为重试持久登记的完整代继续保留。进程突然退出留下且无法验证归属的对象安全保留。
- **FR-011** 相邻版本升级在固定路径上更新已验证的 Studio、Launcher 入口和卸载宿主。现有快捷方式字节保持一致。入口更新由升级意图记录，提交后异常终止可用同一安装包继续。遇到未知内容不覆盖。

## Business Rules, Inputs & Outputs

- **Input** 已构建的 Windows x64 安装包、用户选择、当前安装身份、有效本地桌面范围和 F10 所有权凭证。
- **Output** 已安装、已升级、已卸载、取消、可重试失败或保留项明确的结果。用户配置数据与程序安装位置分离。
- **Rule** 只在明确执行安装或卸载时修改注册和文件。用户发起的正常卸载可清理拥有的桌面入口，升级不得触发该动作。
- **Rule** 文件名、扩展名、链接目标或安装根路径单独都不能证明受管桌面入口归属。卸载沿用 F10 文件身份、内容和当前范围验证。
- **Rule** V1 提供用户主动运行的本地升级。安装与更新没有后台下载、服务或提权。

## Edge Cases

- 同版本重跑、降级、安装取消、写入占用、并发安装、回滚后重试。
- 目标安装目录包含无关内容、重解析点或异常权限。普通用户或 Windows 策略阻止安装。
- 用户手改或移动入口、原路径被替换、Desktop 重定向、记录缺失或损坏，以及程序工作期间启动卸载。
- 实际配置为旧版或未知版本，配置与程序版本独立。安装和卸载不迁移配置。

## Success Criteria

- **SC-001** Windows 11 x64 非提升会话从本地包完成安装，开始菜单可打开 Studio，已安装 Launcher 经 Shell 入口调度隔离目标。验证随包运行时及渲染失败后的原生启动。
- **SC-002** 两个可区分版本完成真实失败回滚、重试、成功升级和降级拒绝。保留 Launcher 路径、旧入口、用户数据及相关文件字节证据。
- **SC-003** 普通卸载及重装通过实际验证。已确认所有权的文件被移除，冲突、重定向与无关对象保留，配置仍能重开。
- **SC-004** 另一个执行者持有升级事务期间，隔离的已安装入口启动一次已提交版本。卸载意图发布后，入口不再启动；同一入口的正常并发启动可等待短暂的程序发布边界。
- **SC-005** 三次相邻升级验证当前版和直接上一版仍可读取，完全拥有的过时版本被移除，更旧代的冲突文件和未登记目录保留原字节。
- **SC-006** 在部分解包后注入失败及在发布时制造冲突，验证本次拥有的暂存内容被清理，未登记对象保留，已登记的升级暂存可以重试。
- **SC-007** 两个不同入口映像完成升级，固定路径和快捷方式字节一致，卸载使用新入口映像。在退役入口后终止安装，重跑同包完成恢复，并验证竞争文件保留。

## Assumptions and Clarifications

- F02、F06、F10、F11 已提供配置、渲染、所有权和诊断合同。安装包封装现有 WPF 与 MotionHost，不引入 Windows App SDK。
- 首个可安装版本使用固定的当前用户安装位置。已发布相邻包的产品升级属于承诺，临时开发发布目录不参与安装升级。
- 默认保留用户数据。删除数据属于用户对具体保留项的显式操作，普通卸载不提供递归清除选项。
- 正式签名与授权发行内容由后续发布门禁验证。未签名的隔离验证包应明示其性质。
- V1 使用本机验收。真实安装和 Shell 路径使用空的产品位置与独立测试数据，故障和所有权冲突使用隔离目录。支持目标仍为 Windows 11 x64 普通用户离线安装。本轮记录实际令牌、已装运行时和联网状态，干净标准账户属于额外兼容性覆盖。
